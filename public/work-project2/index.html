儿童 AI 陪伴硬件 Pro 版｜云端 Agent 对话体验与记忆系统策略优化

V1 记忆能力不可度量、问题不透明；以记忆系统为核心抓手，联动英语分级、家长端看板与 System Prompt 全链路升级云端对话体验，目标提升双端长期留存。

AI 产品经理 · 独立主导 2026 年项目 方案通过技术评审待排期 案例已脱敏

一、项目背景

面向 6–12 岁儿童的 AI 陪伴硬件（桌伴形态），孩子为直接用户、家长为付费决策者。V1 已具备基础长记忆能力，但上线后长留存不及预期，且记忆模块没有系统化评测、问题不透明——只知道用户有抱怨，不清楚问题出在哪一层、影响面多大。

业务目标为提升长留存。拆解路径：长留存依赖关系连续性 → 关系连续性依赖记忆质量 → V1 记忆能力不可度量。第一步不是设计新方案，而是先建立测量能力，把 V1 问题从主观感受变成可量化、可归因的结论。

核心判断：AI 陪伴产品的长期留存，不取决于单次对话有多聪明，而取决于用户第二天回来时是否觉得"昨天的关系还在继续"。聊天记录只是保存内容，记忆负责把内容转化为"它了解我"的体验——这是 D7、D30 与长期迁移成本的真正杠杆。

二、目标用户与核心场景

角色使用场景与诉求
孩子（6–12 岁）设备端日常对话、英语陪练、听故事；低龄孩子听不懂长句、高龄孩子嫌幼稚，核心诉求是愿意多聊几轮
家长（付费方）家长端 APP，关心孩子使用内容、能力进步与安全；诉求是看得见价值、可控，不希望看到原始对话记录（涉及儿童隐私）

三、问题定位与关键决策

3.1 业务目标拆解

业务目标：提升长留存→ 拆出关系连续性→ 关系连续性依赖记忆质量→ V1 记忆能力不可度量

3.2 负反馈调研：记忆是最高频痛点

人工抽检用户反馈与对话日志，按体验问题分类统计。记忆相关负反馈占全部体验类负反馈的 18%，为占比最高的一类。典型表达：

  • "它不记得我喜欢什么"
  • "上次说我喜欢恐龙，这次又说我喜欢汽车"
  • "每次聊都像第一次见"

共性不是"答错了"，而是关系断裂感——对应长留存的判断。

3.3 小范围对照验证：记忆与留存强相关

负反馈只能说明用户抱怨，不能直接推出"做记忆能提升留存"。抽样 500 名用户、控制活跃度变量分组对比：

分组设备端 D7 留存
高频使用记忆功能的用户35%
低频使用记忆功能的用户18%

结论从"记忆有问题"升级为"记忆质量与留存强相关"，记忆系统由此确立为本次优化主线。

3.4 100 条 BadCase 四层归因

定位方向后，进一步回答"记忆哪里坏了"。整理约 100 条记忆相关 BadCase，按系统链路（而非表面现象）分成四类：

归因分类占比典型问题
数据质量问题35%错误记忆、新旧信息冲突未处理
检索召回问题30%应召回时未召回、召回了不适用的记忆
数据合规问题20%写入了不应长期存储的高风险信息
下游应用缺失15%记忆数据未转化为家长可感知的价值

分层直接对应方案的四个方向——写入、召回、合规、下游应用。

3.5 为什么记忆是主线

  • 影响面最大：记忆是系统级能力，贯穿所有对话场景；英语分级、对话长度只是子集；
  • 数据相关性已验证：只有记忆拿到了"与 D7 留存强相关"的对照结论，其他方向只有用户反馈、无留存相关性证据；
  • 是其他体验优化的底座：英语测评结果本身就是一种"能力记忆"，家长端看板展示的也是记忆沉淀的成果——记忆不做好，这些场景优化缺乏基础。

四、解决方案

4.1 记忆系统全链路设计

针对四类 BadCase，从写入到使用全链路重构：

  • 写入筛选：定义"什么信息值得进入长期记忆"的判断规则，将记忆分成三类——用户偏好 / 互动事实 / 临时上下文，明确儿童隐私合规边界，从源头减少脏数据与越界存储；
  • 冲突处理与过期降权：同一信息矛盾时新信息优先、旧信息降权保留而非直接删除；不同类型记忆设差异化有效期，过期自动降权；
  • 意图驱动三层召回：根据当前对话意图判断是否查记忆、查什么、查多少，三层过滤（相关性 → 适用性 → 可执行性），防止"召回了看起来相关但已不适用"的负面迁移；
  • 记忆主动使用规则：定义记忆在什么场景主动融入回复、什么场景保持沉默，平衡陪伴感与不越界；
  • 三层分层存储：短期记忆保留最近几轮对话原文，保证连贯；中期记忆把更早对话自动压成摘要，用摘要代替原文，保留关键信息但压缩 Token；长期记忆把孩子明确表达的偏好和关键信息（"喜欢恐龙""不爱吃胡萝卜"）提取进画像，跨对话永久保留。上下文里只有最近几轮原文 + 历史摘要 + 用户画像，Token 用量可控、关键信息不丢。
设计原则：记忆系统的核心不是"记住所有东西"，而是在长期交互中保持关系连续性——同时明确"该忘记什么"和"什么时候不调用记忆"。

4.2 英语对话分级优化

英语对话是产品卖点场景，但 V1 回复难度随机——低龄听不懂、高龄嫌简单，该场景人均对话轮次偏低。方案：

  • 设计英语能力分级测评体系（4 级），按词汇量与表达能力定级；
  • 按等级输出适配难度的分级回复，让孩子"听得懂才愿意多聊"；
  • 测评结果作为一种"能力记忆"沉淀，反哺个性化体验。

4.3 家长端成长看板联动

家长端把记忆转化为家长可感知的价值：可解释——对话数据转化为统计指标展示（不暴露原始对话，儿童隐私）；可控——家长端设置提供个性化记忆开关，可随时开启/关闭孩子的个性化记忆，关闭即停止写入与召回、已有记忆冻结；可处置——数据删除绑定设备/账号格式化与重置，不单独设删除入口。对应 BadCase 归因中"下游应用缺失"的问题，让沉淀的记忆转化为家长可感知的价值。

4.4 System Prompt 策略落地

上层能力最终落到 System Prompt 被模型执行：

  • 记忆主动召回的触发逻辑
  • 分龄化对话长度控制（低龄简短、高龄可扩展）
  • 英语分级回复策略
  • 讲故事模式下的安全边界拦截（统一拦截恐怖 / 不适龄内容生成）

五、评测体系（从 0 到 1）

V1 最大的问题是能力不可度量。方案设计同步搭建评测体系，使新效果可被验证：

  • 四个评测维度：写入有效率、召回准确率、适用性正确率、记忆使用有效率，每个维度拆成可量化子项并加权打分；
  • 50 条评测集：覆盖 5 类场景 × 4 档难度，来源混合真实用户问题、边界用例与 BadCase 回流；
  • 三层评测流程：模型自动打分（全量回归）+ 人工抽检（发版前复核）+ 线上反馈回流（点踩 / 追问 / 跳出转化为新题）；
  • 调优集与验收集分离：避免模型"刷榜"，发版决策以验收集成绩为准。

七、复盘

  • 数据驱动的边界：本次立项用 500 用户小样本抽样验证，严格来说不替代长期 A/B 实验；小样本的作用是为方案提供方向性证据。方案已设计上线后 A/B 因果验证：设备端开关分组（实验组开三层记忆、对照组关记忆回退 V1）+ 联动模块分批上线避免混叠，主指标双端 D7/D30，过程指标记忆使用有效率——证明留存提升确由记忆带来；
  • 方案分批落地：四大模块不应一次性全排，记忆系统先行、英语分级与看板跟进，按批次迭代，每批由评测集回归兜底；
  • 记忆最危险的失败不是没召回：而是召回了一条看起来相关但已不适用的信息，Agent 仍自信执行（负面迁移）——三层召回过滤的核心防护点；
  • 体验连续性 ≠ 关系深度：该忘的要忘、该沉默时要沉默，给孩子和家长保留控制权——儿童 AI 陪伴的合规与产品底线。
